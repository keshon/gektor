## Подтвержденные дефекты

### F01 · P1 · Первый запуск `agent.exe -tui` завершается до открытия интерфейса

**Место:** [cmd/agent/application.go:43](../cmd/agent/application.go#L43).

При отсутствии пользовательских настроек код подставляет профиль `~/.tars/profiles/llama-external.json`. Файл туда не копируется и не создается. `resolveLaunch` пытается открыть его и возвращает ошибку. Профиль в репозитории `profiles/llama-external.json` не используется как fallback.

**Воспроизведение:** `runApplication([]string{"-tui"})` с пустым домашним каталогом в TestMain. Получено `open ...\.tars\profiles\llama-external.json: The system cannot find the path specified.` Backend вообще не вызывается. Это ломает основной quick start из README на новой установке.

**Исправление:** определить один путь первого запуска: встроенный профиль или создание пользовательского профиля из шаблона, с рабочим workspace по умолчанию. Проверять именно полный bare-launch, а не только `applicationArgs`.

### F02 · P2 · Стандартный TUI launcher проверяет другой порт и блокирует альтернативные backend

**Место:** [run-tui.cmd:6](../run-tui.cmd#L6), [run-server-llama.cmd:21](../run-server-llama.cmd#L21).

`run-tui.cmd` жестко задает и проверяет `127.0.0.1:9931`. Серверный launcher по умолчанию стартует на `8080`, что также указано в README. При штатном запуске сервер доступен, а TUI launcher сообщает, что его нет. `.env` в TUI launcher не читается.

Проверка выполняется до передачи `%*` в агент. Поэтому документированный `run-tui.cmd -backend-kind kobold -backend http://127.0.0.1:5001` тоже требует посторонний сервер на `9931`.

**Подтверждение:** прямое сопоставление control flow обоих скриптов и README; серверы не запускались.

**Исправление:** разрешать итоговую конфигурацию до preflight и проверять выбранный endpoint. Желательно оставить разрешение конфигурации Go-коду вместо второй реализации в batch.

### F03 · P2 · Изменение Generation при температуре по умолчанию не применяется

**Место:** [internal/tui/settings/fields.go:27](../internal/tui/settings/fields.go#L27), [internal/config/profile.go:68](../internal/config/profile.go#L68).

Форма помещает в редактируемое значение температуры строку `default (0.4)`. Парсер принимает только слово `default` или число. При изменении одного Response budget или Context window Draft повторно разбирает всю страницу и отвергает нетронутую температуру.

**Воспроизведение:** реальная цепочка `PageFields → Draft.Visit → изменение max → Draft.Store → Draft.Resolve`. Получено `generation: temperature must be a number, or "default"`.

**Исправление:** хранить в поле каноническое значение `default`, а эффективные `0.4` показывать отдельной подписью. Добавить round-trip проверку всей страницы с изменением соседнего поля.

### F04 · P2 · Применение Settings сбрасывает параметры проверки и аудит

**Место:** [cmd/agent/application.go:165](../cmd/agent/application.go#L165).

После смены настроек `runApplication` восстанавливает argv через `applicationArgs` и `retainedAgentOptions`. Сохраняются только `allow`, `deny`, `mcp`, `reasoning-budget`, `max-steps`. Теряются `verify-cmd`, `audit`, `no-verify`, `yes`; `nudges` также теряется, если задан только CLI-флагом и еще не сохранен в preferences.

**Воспроизведение:** исходные `verify="go test ./...", audit="audit.jsonl", nudges=off, noVerify=true, yes=true` после реконструкции превращаются в `verify="", audit="", nudges=full, noVerify=false, yes=false`.

Особенно существенно исчезновение `verify-cmd`: после применения Settings механическая проверка результата больше не выполняется, хотя оператор выбрал ее при запуске. Теряется и журнал разрешений.

**Исправление:** переносить структурированную конфигурацию запуска и явно определить поля, которые Settings меняет. Проверить полный цикл handoff с установленными execution options.

### F05 · P2 · Финальный sweep direct-session отправляет находки мимо событий TUI

**Место:** [internal/run/session.go:141](../internal/run/session.go#L141), [internal/run/session.go:160](../internal/run/session.go#L160), [internal/run/session.go:198](../internal/run/session.go#L198).

В `build` создается локальная копия Env с новым Checks, который публикует `finding` в event stream. Однако `Run` и `Resume` вызывают Sweep на исходном `s.cfg.Env`, а не на этой копии. Поэтому глубокий проход использует старый sink или вообще ничего не сканирует, если исходный Checks nil. Находки post-write и session-end также оказываются в разных dedupe-кэшах.

**Воспроизведение:** необернутый эффект создал `stray.txt` с маркером приватного ключа. Outcome содержит `files:[stray.txt]`; старый sink получил одну находку, `OnEvent` — ноль. В TUI исходный sink относится к CLI, поэтому результат может дополнительно попасть в консоль поверх интерфейса.

**Исправление:** сохранять подготовленный Env/Reporter на весь запуск и использовать его для per-edit и session-end, публикуя обе стадии одним каналом.

### F06 · P2 · Mission sweep проверяет список файлов до исполнения миссии

**Место:** [internal/mission/phases.go:156](../internal/mission/phases.go#L156).

`defer r.Env.Sweep(m.Mutated)` вычисляет аргумент при регистрации defer. У новой миссии срез пустой. Исполнители позднее присваивают `m.Mutated = unionPaths(...)`, но отложенный вызов уже хранит прежний срез.

**Воспроизведение:** новая миссия прошла plan/execute/verify, observer зарегистрировал `index.html` с маркером приватного ключа, миссия успешно завершилась с `Mutated:[index.html]`, а sweep выдал ноль находок. Изменение сделано вне file-tool wrapper, чтобы требовался именно глубокий проход.

Штатные sweep-тесты этого не ловят: они запускают уже Done/Failed миссию с заранее заполненным `Mutated`.

**Исправление:** `defer func() { r.Env.Sweep(m.Mutated) }()` и тест новой миссии, которая создает файл во время исполнения.

### F07 · P2 · Продолжение после лимита теряет уже измененные файлы

**Место:** [internal/agent/budget.go:54](../internal/agent/budget.go#L54), [internal/agent/run.go:20](../internal/agent/run.go#L20).

`BudgetContinue` вызывает `Resume` на том же агенте. Вход в `run` обнуляет RunReport и LastRunMutations. Внешний CLI/run.Session после этого видит только вторую часть работы. Файлы первой части исчезают из итогового outcome и списка для sweep.

**Воспроизведение Bugbot:** при MaxSteps=1 до согласованного продолжения `MutatedPaths:[a.txt]`; после успешного продолжения без новых записей — `Outcome:completed, MutatedPaths:[]`. Файл на диске остается.

**Исправление:** агрегировать отчеты обеих частей одного пользовательского запуска: пути, счетчики, предупреждения и сведения о verification. Не переносить старый успешный verdict на новые записи без проверки.

### F08 · P2 · Продолжение обещает 25 шагов, но дает исходный лимит

**Место:** [internal/agent/budget.go:38](../internal/agent/budget.go#L38), [internal/agent/budget.go:54](../internal/agent/budget.go#L54).

Вопрос оператору и harness-note обещают `+DefaultMaxSteps`, то есть 25. Затем выполняется `Resume` без изменения `cfg.MaxSteps`. Реальный дополнительный бюджет равен исходному лимиту, потенциально с отдельным todo-funding.

**Воспроизведение Bugbot:** при исходном MaxSteps=1 после подтверждения отчет продолжения все еще показывает MaxSteps=1. При большом пользовательском лимите оператор, наоборот, получает больше обещанного.

**Исправление:** выбрать явную семантику продолжения и применять ровно тот бюджет, который назван в вопросе.

### F09 · P2 · Редактирование You стирает имя ассистента

**Место:** [internal/config/edit.go:50](../internal/config/edit.go#L50), [internal/tui/settings/fields.go:54](../internal/tui/settings/fields.go#L54).

Страница You содержит только `user` и `persona`, но ApplySection безусловно присваивает Identity.Name из отсутствующего поля `name`. Любое изменение этой страницы очищает имя ассистента в профиле и меняет его вклад в итоговый prompt.

**Воспроизведение:** через PageFields/Draft изменено только имя пользователя. До: `assistant="TARS"`; после: `assistant="", user="Alice"`. Независимо воспроизведено Bugbot.

**Исправление:** изменять только присутствующие ключи либо вернуть редактирование имени ассистента в контракт формы.

### F10 · P2 · Запуск без профиля создает профиль с другой identity

**Место:** [cmd/agent/application.go:128](../cmd/agent/application.go#L128).

`launchProfile` сохраняет DefaultUserName и DefaultSystemPrompt вместо уже разрешенных `o.userName`, `o.systemPrompt`, `o.postHistory`. Поэтому Settings/inspect отображают не тот prompt, который получил действующий агент. После применения настроек и рестарта исходные CLI identity-параметры не восстанавливаются.

**Воспроизведение:** при `-tui -system-prompt CUSTOM -user-name Alice -post-history POST` эффективная конфигурация содержит эти значения, а сгенерированный профиль — `User`, `You are a helpful assistant.`, пустой PostHistory.

**Исправление:** строить профиль из полной разрешенной конфигурации. Проверять эквивалентность эффективной identity до и после handoff.

### F11 · P2 · Текущий HEAD не пройдет format job CI

**Место:** [.github/workflows/ci.yml](../.github/workflows/ci.yml), например [cmd/agent/agent.go:16](../cmd/agent/agent.go#L16).

У 39 из 327 отслеживаемых Go-файлов содержимое HEAD отличается от результата gofmt. Проверялось содержимое `git show HEAD:<path>` с нормализованным LF, поэтому это не Windows CRLF-артефакт. Среди причин — порядок импортов и отступы, например участок PhaseExecute в mission/phases.go.

**Воспроизведение:** для каждого отслеживаемого `.go` файла передать LF-содержимое HEAD на stdin `gofmt` и сравнить stdout с исходными байтами. CI на Linux запускает `gofmt -l .` и завершится ошибкой при непустом списке.

**Исправление:** отдельный форматирующий проход перед слиянием. В данном аудите файлы не форматировались, чтобы сохранить исходный срез для разбора дефектов.

### F12 · P2 · `-context-limit` игнорируется для локальных backend

**Место:** [cmd/agent/agent.go:179](../cmd/agent/agent.go#L179).

Override применяется только в ветке `backend-kind openai`. Для llama/kobold локальная переменная безусловно получает результат MaxContextLength, несмотря на описание флага «overriding the backend probe». Значение, введенное в Settings → Generation, также не определяет эффективный контекст локального запуска.

**Воспроизведение:** локальный HTTP-stub сообщил `/props n_ctx=4096`, CLI запросил `-context-limit 8192`. JSONL сначала содержит `run_start context_limit=8192`, затем `context context_limit=4096`; агент работает с 4096. При неудаче probe устанавливается 0, даже если оператор явно задал лимит.

**Исправление:** либо действительно применять явный предел с корректной семантикой безопасности, либо убрать обещание override и сделать поле фактически read-only для локального backend. Сейчас UI/CLI обещают недостижимое поведение.

### F13 · P2 · Read-only отчет ошибочно признается заявлением о собственных изменениях

**Место:** [internal/agent/finish.go:156](../internal/agent/finish.go#L156), [internal/agent/finish.go:266](../internal/agent/finish.go#L266).

claimsFileEffects ищет сочетание имени файла и слов вроде `removed`, `added`, `fixed`, не различая описание кода и заявление о собственном действии. Проверка действует даже при SkipVerify и отсутствии инструментов записи.

**Воспроизведение Bugbot:** read-only агент четыре раза отвечает `The function was removed from main.go.`. Вместо ответа получается `announced completion 3 times without writing anything`. Planner/Inspector принципиально не могут выполнить требуемую запись.

**Исправление:** связывать требования о записи с контрактом задачи и наблюдаемыми возможностями роли. Как минимум исключить роли без mutation-capabilities из такого отказа.

- **tui/components:** cell, completion, composer, form, gate, popup, selection, transcript/viewport — покрыты общим тестовым запуском; completion не имеет собственного тестового пакета и проверяется через вызывающий TUI. Новых изолированных дефектов не подтверждено.
- **tui/settings:** Draft, fields, catalog, picker/update/view, стык с ApplySection; F03/F09 подтверждены через собранный контракт формы.
- **conventions + scripts/docs/CI/profiles:** enforceable conventions, build и launch scripts, расхождения quick start; F01/F02/F11.

## Результат исправлений

- **F01/F02:** первый запуск получает встроенный профиль, а launcher только собирает и запускает приложение. Настройки backend разрешаются в Go. Дополнительный `-workspace` сохраняет выбранную модель; явные флаги имеют приоритет.
- **F03/F09/F10:** температура хранится в редактируемом виде `default`, эффективное значение показано отдельно; страница You сохраняет имя ассистента; сгенерированный профиль сохраняет фактическую identity CLI.
- **F04:** повторный запуск получает разобранную конфигурацию. Удалены whitelist `retainedAgentOptions`, повторная сборка argv и дублирующие `explicitNames`/`thinkingSettings`. Политика, verify-cmd, audit и временный API key продолжают действовать, а профиль/harness берутся из примененных настроек. Старые task/resume/image аргументы не воспроизводятся заново.
- **F05/F06:** per-edit и финальная проверка сессии используют один event reporter; mission sweep читает итоговый список файлов при выходе.
- **F07/F08:** подтвержденное продолжение дает ровно 25 шагов без дополнительного todo-funding. Пути, счетчики и предупреждения обеих частей объединяются, пути дедуплицируются; старый verification verdict не выдается за новую проверку. Логика budget gate теперь находится в [internal/agent/suspend.go](../internal/agent/suspend.go).
- **F11/F12:** все существующие отслеживаемые Go-файлы проходят gofmt; явно настроенный context-limit используется и для локального backend, включая отказ probe.
- **F13:** удалена эвристика `claimsFileEffects` со словарем глаголов и regex. Обязательная запись определяется явным контрактом VerifyOnZeroWrites, которым пользуются mission workers. Обычное объяснение кода не требует искусственной записи файла.

Дополнительно унифицирована конфигурация пяти ролей; nudge-режим наследуется ими одинаково. Streaming запрашивает реальные usage, сохраняет cached tokens и использует общую wire-схему с unary. Оценка токенов остается fallback и явно помечается Estimated.

Удалено шесть Go-файлов без добавления новых: четыре производственных и два тестовых. Сервисы и их создание собраны в services.go; budget gate — в suspend.go; состояние application — в application.go; preset API — в prompts.go. Удалены неиспользуемые поля. Реестр роли и UI-компоненты сохранены.

## Упрощение после аудита

Предыдущий раздел описывает снимок исправлений, сохраненный в коммите `9cdf725`.
После него выполнены все пять согласованных архитектурных изменений:

- Удален mission: исполнитель, планировщик, ledger, scoring, replan, worker/reviewer, CLI/RPC/TUI-ветки, launcher и prompts. Остались один агентский цикл, Plan/Act и ограниченное делегирование. Механические проверки перенесены в cmd/eval; удалены три сценария снятого режима, остальные 15 проходят dry-валидацию.
- Todo хранит список работы и не меняет лимит шагов. Незавершенный список не блокирует ответ. Продолжение требует явного согласия оператора и дает ровно 25 шагов, сохраняя результаты предыдущей части.
- Удалены reasoning-wrap, обязательная модельная самопроверка, zero-write retries, эвристики «застрял/долго исследует» и дополнительный closing-вызов после лимита. Восстановление осталось для реальных ошибок протокола и переполнения контекста. verify-cmd запускается один раз; ошибка команды завершает run с ошибкой, без нового LLM-запроса.
- Повторное чтение, повторная запись и перезапись существующего файла разрешены. Удалены repeat cache, блокировка второй записи и сравнение похожести содержимого. Сохранены права, проверка путей, корректность патчей, ограничения вывода и порядок мутаций.
- Полный inventory выполняется на старте и при завершении, после проверки команды. Финальный обход работает и после отмены с отдельным лимитом 30 секунд. Обхода после каждого шага больше нет.

Удалены настройки nudges, reasoning-budget и no-verify. Старые сохраненные поля читаются, но исчезают при следующем сохранении настроек. Step limit унифицирован для CLI/TUI/RPC. Документация описывает текущую архитектуру.

Производственных Go-файлов стало **143 вместо 155**, чистое сокращение — **4661 строк Go**, без учета удаления тестов и prompts.

Проверено:

- Полные обычные и race-тесты; vet и сборка.

- Независимый Bugbot не обнаружил подтвержденных регрессий.

Скорость и качество реального LLM этим прогоном не измерялись; backend в smoke-тесте детерминированный.
