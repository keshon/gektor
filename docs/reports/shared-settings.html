Shared menu and settings

14 October 2026 · actual TUI renderer fixtures · implementation ready for live acceptance

Session · Mode · Chat / Agent · View · Settings · Voice · Help

  • Model, Generation, Speech, Profiles and Application share one workspace. Character and Prompts are Chat-specific.
  • Mode switches retain the session directory, title and draft. Agent starts in Plan when entering Agent or opening a saved session.
  • Common-launch sessions use var/chats. settings.json stores their mode and profile; conversation.json and state.json retain the two native history formats. Agent checkpoint journals retain prior revisions.
  • Opening a saved session restores its mode and profile. Older Chat archives without settings use the current service profile.
  • Apply with no changes does nothing. Model/service changes may restart owned processes, while retaining the conversation. No turn starts from Apply.
  • Voice → Stop playback cancels speech while text generation continues. Esc stops the whole turn.
  • Agent sampling now respects temperature. Explicit CLI permission and MCP options remain in effect across handoffs within the running application.
  • Unsupported-runtime startup failures explain the recovery path through Settings → Model.

Live acceptance

  1. Run agent.exe -tui. Choose a supported installed model in Settings → Model; type one message.
  2. Stage a model change, visit another category, then return and Apply. Verify history, title and draft remain.
  3. Choose Mode → Agent, select an existing workspace, Apply. Verify Plan, then explicitly select Act when needed.
  4. Switch back to Chat, then use Session → Open. Verify one session entry and its saved mode/configuration.
  5. Enable voice and test recording, response playback and interruption. Check that voice input cannot approve a tool permission.

Unit and race checks cover local transitions and persistence. These fixtures do not establish microphone, GPU, acoustic or live model quality.
